How Caching Works

When a task is requested, the server first checks the cache:

✓
If the task exists in the cache:
  • CACHE HIT
  • Return cached data from in-memory RAM
  • MongoDB is not queried (ultra-fast)
✕
If the task is not in the cache:
  • CACHE MISS
  • Query MongoDB collection
  • Store the result in cache with 60s TTL
  • Return the fresh data
🔄
Cache Invalidation:

When a task is created, updated, or deleted, the related cache entries (all_tasks and task_<id>) are invalidated so clients never receive stale data.
